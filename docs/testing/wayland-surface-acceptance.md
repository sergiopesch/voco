# Private Wayland surface acceptance

The existing `scripts/test-native-wayland.sh` harness supports an additional opt-in journey. Set `VOCO_WAYLAND_CAPTURE=1`, `VOCO_WAYLAND_SURFACE_JOURNEY=1`, and `VOCO_DEBUG_CAPTURE_AUDIO=1` with the usual `VOCO_WAYLAND_BACKEND=nested-x11`, extracted dependency, exact packaged application, pinned model, and fresh evidence-directory variables.

The supported journey remaps the idle popover **before** recording, then invokes its visible Hide to tray control and verifies it is hidden before the recording toggle. An open panel deliberately consumes the first toggle as dismissal; the harness does not mistake that for capture startup. During synthetic playback, actual tray Open must be refused by the application's recording guard. After recording, actual Open must expose normal Copy. Because clipboard readback can change focus, the journey explicitly invokes Open again before requiring and clicking visible Settings, reopens the transcript, maps a separate native focus target, verifies real compositor focus and blur dismissal, and reopens visible Copy with actual clipboard readback. It does not bypass the application's state guard. No surface, recording, or clipboard result is supplied by a mock.

`VOCO_WAYLAND_DISMISS_TARGET=1` remains an explicitly separate fixture-dismissal scenario; it cannot replace or establish passing foreground-target tray activation. The default scenario retains the original target throughout.

The public 16 kHz `84-121123-0000.wav` fixture is checksum-verified before playback. Debug capture is permitted only in this isolated synthetic-audio journey. Capture acceptance is prospectively fixed before packaged execution: captured length must cover the entire fixture; one global waveform alignment is selected using an energy-envelope search followed by sample refinement; whole-fixture normalized correlation and each speech-energy quarter must be at least 0.90. Speech-energy quarters are determined solely from the reference using RMS at least 0.005. Every quarter's correlation and RMS, the global offset, sample counts, durations, captured SHA, and capture-stage trace are retained. Quiet quarters are reported but do not establish waveform fidelity. This is a continuity check, not sample-perfect equivalence or physical microphone qualification.

Copy must be enabled, visible and showing with positive bounds. Before each Copy, a distinct sentinel is written and verified on the private clipboard, with its foreground owner retained until replacement. A screenshot is saved immediately before each Copy action; the final screenshot is a separate post-action/failure observation and is not substituted for pre-action visibility. Its accessible action must replace the sentinel with exactly the four expected words on the private Wayland clipboard. A hidden control is never used as a passing substitute. Hotkey traces and any debug captures are copied in final cleanup even if acceptance fails before transcription. Earlier failed runs remain unchanged; missing historical traces cannot be reconstructed. Errors and screenshots are retained in the existing evidence directory. No new Python dependencies are required.

Run the no-inference scoring checks with `python3 scripts/test-wayland-capture-continuity.py`. These cover complete audio at three sample offsets, a missing speech quarter, constant input, truncated audio, and removed interior time padded back to the original length. Packaged surface acceptance remains pending until the exact rebuilt binary executes this journey.

Before both Copy actions, a bounded pixel gate now samples the private screenshot at the fixture's configured centered frame plus the Copy control's window-relative bounds. The geometry must fit the screenshot. At least half the panel samples must be neutral dark pixels (channels 8–65, spread ≤25), half the button pixels light (minimum channel 110, spread≤50), and 1.5% dark glyph pixels (maximum channel<80) within the content rectangle: 18px inset horizontally (matching CSS padding), and the middle half of button height, excluding rounded corners/borders. These explicit style-specific criteria reject black frames, unrelated white fixtures and blank light rectangles; they are not a general OCR/readability proof. Accessibility showing/enabled/visible states and geometry must remain identical immediately before and after the screenshot. Each attempted screenshot and measured fractions is retained, and failure remains failure after the bounded wait. GTK Wayland reports frame origin (0,0) even when the compositor centers it; that reported origin is retained but is not treated as a physical screen coordinate. This gate is deliberately restricted to the configured single 1280×900 Weston kiosk output and requires the actual reported frame size 420×660, locating its expected center at 430,120. The fixture-layout assumption is recorded per attempt; it does not establish positioning on arbitrary compositors.
