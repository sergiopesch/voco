# VOCO 2026.0.69

Dictation is the first step. We're building the voice layer for Linux: private,
local, and under your control.

**Today: private dictation for Linux.** Press a shortcut, speak, and your words
appear where you are typing, while you speak.

This release smooths VOCO's first minutes, above all for the snap from the Snap
Store and Ubuntu's App Center. VOCO now starts when you sign in, the snap's setup
gets its GNOME panel installed in fewer steps and carries on by itself, and VOCO
says plainly when a processor can't run its speech recognition. It runs on the
same systems as 2026.0.68: Ubuntu 24.04 and 26.04, Debian 13 and Fedora 44. The
[changelog](../../CHANGELOG.md) lists every change.

## What's new

- **VOCO starts when you sign in.** It starts quietly in the top bar or tray,
  without a window, once setup is complete. Turn it off in **Settings** with
  **Start VOCO when you sign in**. If you finished setup on an earlier VOCO, it
  starts at login from now on too.
- **The snap's setup is simpler.** When VOCO needs its GNOME panel, setup shows
  that one step, and carries on by itself once the panel is installed: GNOME
  loads a first install at once, with no sign-out. If the website's Install
  button asks for GNOME's browser integration, **Install without the website**
  copies a command that opens GNOME's own install prompt instead. On X11, where
  the snap types without the panel, setup calls it optional.
- **Help and messages fit the snap.** Help links to the snap's own guide and no
  longer lists features the snap doesn't have, and the permission messages say
  where to allow them in Settings.
- **A clear message on a processor VOCO can't use.** Without AVX2, FMA and
  F16C, VOCO now says so at startup, names what's missing and doesn't start
  dictation, where it used to show a generic error. The store and package
  descriptions name the requirement.
- **Install update works on Debian 13, Ubuntu 26.04 and Fedora 44.** Their
  password prompt passed on a setting that made VOCO's update helper refuse its
  own download folder. From this release on, Install update works there too.
- **The GNOME panel is version 22**, as published on
  [extensions.gnome.org](https://extensions.gnome.org/extension/11710/voco/). It
  is split into small parts that each clean up after themselves, follows GNOME's
  reduced motion, reconnects when a busy desktop delays VOCO's answer, and offers
  Stop only while there's a dictation to stop.
- **Panel setup names another copy of the panel in your home folder,** such as
  one from extensions.gnome.org, that GNOME loads instead of the package's.

## Upgrade

**The snap** updates itself from the Snap Store. If it says an update is
waiting, choose **Quit VOCO** in the tray or panel menu, then open VOCO again.

**From 2026.0.66 to 2026.0.68**, open **Settings**, then **Updates**, and choose
**Install update**. Your system asks for an administrator's password, and VOCO
restarts on this release. **On Debian 13, Ubuntu 26.04 and Fedora 44**, those
releases' own update helper refuses, so upgrade once with the guided installer
below; from this release on, Install update works there.

From an earlier version, or on those three systems:

1. Finish any dictation, and copy anything you need from Review.
2. Quit VOCO with **Quit VOCO** in the tray or GNOME panel menu.
3. Run this release's guided installer, or repeat the
   [manual install](../install.md#manual-install):

   ```bash
   wget -qO voco-install https://raw.githubusercontent.com/sergiopesch/voco/voco.2026.0.69/install && bash voco-install
   ```

Your settings are kept. **On GNOME, save your work and sign out and back in
after upgrading**, so GNOME loads the new panel. Until then it keeps the earlier
one, which still works with this VOCO. `voco --check-panel` says when a sign-in
is still needed.

## Known limits

- The snap types on GNOME on Wayland only through the VOCO panel, which a snap
  can't install itself: setup sends you to extensions.gnome.org for it. On other
  Wayland desktops the snap can't type; use the `.deb` or RPM.
- Install update needs your system's password prompt, which your desktop
  provides. Over SSH, or in a session that isn't the active local one, the
  system refuses it; use the release's installer instead.
- Dictation replaces what the clipboard and the primary selection hold.
- My words makes VOCO lean toward your words but can't guarantee them: one that
  sounds exactly like another, or that VOCO hears as a different word, can still
  come out wrong. **Say it** shows what VOCO hears, and **Teach VOCO** fixes a
  version it gets wrong.
- A taught version made only of everyday words changes those words every time
  you say them.
- Where you pause between sentences, the full stop often comes a word late or
  not at all, with no capital after it. VOCO doesn't add one, because it would
  also end sentences where you only pause to think
  ([the measurements](../../research/pause-sentence-ends-2026-10/README.md)).
- After a pause, a rich-text field can make the next space a no-break space, at
  most one for each pause, and may keep the space Stop adds as one.
- On Wayland, session checks are not an atomic lock: switching sessions after a
  check can still redirect keys. An unavailable logind status permits pasting.
  See the [input-device security model](../security/README.md#input-devices).
- GNOME's own microphone indicator can still shift the top bar's icons while the
  microphone is in use.
- On Debian 13 and Fedora 44, VOCO has an icon in the top bar only once the GNOME
  panel is on, because they don't turn on an AppIndicator extension.
- DNF says it skipped OpenPGP checks for the RPM file. The installer verifies the
  signed checksums first, which is what authenticates the package.
- VOCO discards a recording it can't confirm is complete, and says so at Start.
- When it pastes, VOCO can't tell a password field from other fields. Don't
  dictate into one. The Chromium extension refuses password fields.
- Don't dictate while a terminal program is waiting for an answer, such as a
  coding agent's permission prompt: it may read your words as typed keys. See
  [Where your words go](../everyday-use.md#where-your-words-go).
- VOCO knows the screen is locked only when the desktop reports it to logind, as
  GNOME does.
- Apps that remap Shift+Insert, remote desktops and virtual machines may not
  accept the paste. Custom editors and other compositors need their own testing.
- On Wayland, a shortcut other than Alt+D or Alt+Shift+D works only when you bind
  it to `voco --toggle` in your desktop's keyboard settings.
- In the snap on X11, a microphone permission granted after VOCO started takes
  effect only after a restart; VOCO says so.
- VOCO recognizes English only. It needs x86-64 with AVX2, FMA and F16C, and
  glibc 2.39 or later.
