# VOCO 2026.0.42

A reliability and contributor-tooling release for local English dictation on Linux.
It combines the .40 and .41 development milestones; neither was a public release.

## What changes for users

- Automatic dictation requires verified AudioWorklet capture. A failed capture
  setup preserves available audio with a completeness warning instead of silently
  starting automatic delivery through an unverified fallback.
- Retry for interrupted normal dictation uses the bundled NVIDIA model offline.
  Review and Copy the result; recovery never silently pastes or replays text into
  the current window. No Whisper download is required for this recovery path.
- Cancellation and stale-session cleanup are isolated. Invalid recovery requests
  clean up only their own worker, leaving live dictation and newer sessions intact.
- The recording lifecycle is split into focused modules with regression coverage.
  Tauri and serde_with updates accompany the existing glib iterator safety backport.

The speech model, context 1 and four-thread default are unchanged. This release
does not claim a recognition or perceived-speed improvement from the small tuning
experiments.

The Debian package explicitly declares its desktop paste helpers and C/C++ ABI
minimums. Setup instructions distinguish shortcut handling from text delivery.
Generated Python caches are excluded from packaged documentation.

## For contributors

The 19-chapter [Inside VOCO guide](../guide/README.md) explains the release architecture,
offline recovery and TypeSafe evaluation. Its source links use a pinned .42 snapshot.
[Twenty measurement criteria](../testing/typesafe-evaluation.md) separate start/stop,
first words, ongoing word lag, punctuation, exact accuracy, meaning and delivery safety.
The [dated before/after study](../testing/typesafe-results-2026-09-19.md) keeps its .41
runtime identity and reports rejected experiments as well as useful findings.

The optional research CLI sends only explicitly approved public/synthetic text;
TypeSafe is not part of the installed app. Failed API parsing preserves valid
receipts and subsequent case attempts. CI actions are commit-pinned, tokens are
read-only, jobs have deadlines and four checks protect the default branch.

## Installation and verification

Use the complete amd64 `.deb` and checksum file from this version's release.
Verify the detached checksum signature with the published `KEYS` fingerprint,
then verify package hashes before installation. See [install](../install.md).
The previous .39 package remains available for rollback; its unsigned tag and
assets are unchanged. No hosted installer workflow is enabled.

The package's dependency baseline is Ubuntu 24.04 or later, glibc 2.39,
libstdc++ 13.2.0 and an AVX2/FMA/F16C x86_64 CPU. The release attachment
`voco_2026.0.42_provenance.json` records source, package, runtime and completed
checks. A draft or source version does not establish public availability.

## Known limits

- Physical microphone and application behavior vary by audio stack, compositor,
  focus and editor. Isolated GTK/X11 userspace tests are not universal Linux certification.
- Recovery may temporarily run a second model process and consume more memory.
  A renderer crash between recovery requests may leave one idle recovery process
  until another recovery or application exit; normal cancellation is cleaned up.
- Audited punctuation references and word-end timestamps are still required for
  punctuation-accuracy and true word-display-lag claims. No worldwide ranking is made.
- The model/native payload is pinned and distributed with notices, but its complete
  independent conversion/native build is not yet reproducible from a fresh source
  checkout. [Provisioning](../linux-packaging.md#runtime-provisioning) explains this boundary.
- AppImage, Flatpak, Snap, RPM and Arch distribution channels remain experimental.
  The security policy retains maintenance warnings and the scoped rand advisory.
